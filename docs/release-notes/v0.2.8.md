pictkura 0.2.8 makes failures visible, fixes an import that could drop a photo, and fits the
window to your screen.

## What's new

### Importing

- **Two photos with the same name in different folders are both imported.** Example:
  `DCIM/100MSDCF/DSC00001.ARW` and `DCIM/101MSDCF/DSC00001.ARW`. This also applies when the
  names differ only in upper and lower case.
  - Before: only one was copied, and the import reported success for both.
- **A `?` mark in the import wizard** means the same name is on the card more than once, so
  whether the photo in your library is this one is not yet known.
  - The row stays selected.
  - Pressing import checks the contents. A photo that is already there is not copied again.

### When something fails

- **Failures are recorded in `pictkura.log`.**

  | | |
  |---|---|
  | Location (Windows) | `%APPDATA%\dev.harusame.pictkura\pictkura.log` |
  | Location (macOS) | `~/Library/Application Support/dev.harusame.pictkura/pictkura.log` |
  | To open it | Settings → About → **Open the log** |
  | Created | Only when something fails. No file means nothing has failed. |
  | Sent anywhere | No. It stays on your computer. |
  | Language | Always English, so it can be pasted into an issue as it is. |

- **Failure messages appear just below the toolbar**, in front of Settings and the import
  wizard. Click to dismiss, or wait 8 seconds.
- **Failure messages are in the app's language.** Text that comes from Windows or macOS
  itself stays in the system's language.
- **Failures about a file name the file.**
- **Twelve actions that used to fail without a word now show a message.**

### Settings

- **`Ctrl`+`,` (Mac: `⌘`+`,`) opens Settings**, from the grid or from the photo viewer.
- **Mac: pictkura → Settings…** in the menu bar also opens it.

### Windows AutoPlay

- **On a new install, pictkura is not added to AutoPlay until you turn it on.** To turn it
  on: Settings → **When you insert a USB drive or SD card** → **Offer pictkura in the
  AutoPlay choices**.
- **If you are upgrading, nothing changes.** Your AutoPlay entry and the setting stay as
  they are.

### The window

- **The window opens at a size that fits the display it opens on.** It is moved only if it
  would otherwise hang off the screen.
  - Before: on a 1366×768 display, or at 150% scaling, the window could open larger than the
    screen, with its lower edge out of reach.
- **Smallest window size: 960×520.** On a display too small for that, the smallest size is
  lowered to fit.

### Keys

- **`Esc` closes what is in front**: the import wizard, the right-click menu, or Settings,
  even when a photo is open behind it.
  - Before: `Esc` could close the photo behind them instead, and with photos marked ✕, the
    "move to Recycle Bin" confirmation could open where it could not be seen.
- **The first `Esc` works after the photo viewer has been left untouched.**
  - Before: the first key press was lost, and a second `Esc` was needed.
- **`Ctrl`+`F` (`⌘`+`F`) no longer stars the photo.** Plain `F` still does.

## Downloads

| You want | File |
|---|---|
| Windows 10/11, the usual case | `pictkura_0.2.8_x64-setup.exe` — no administrator rights |
| Windows, machine-wide install (for administrators) | `pictkura_0.2.8_x64_ja-JP.msi` / `_en-US.msi` |
| Windows, no installer | `pictkura_0.2.8_x64-portable.zip` |
| macOS 11+ (Apple Silicon) | `pictkura_0.2.8_arm64.zip` |

Neither build is code-signed, so Windows shows SmartScreen and macOS shows Gatekeeper on
first launch. The [README](https://github.com/Harusame64/pictkura#readme) walks through
both, including the extra steps macOS 15 needs.

## Upgrading from 0.2.7

- **Windows**: run the new installer over the old one.
- **macOS**: unzip the new `pictkura.app` and replace the old one. The Gatekeeper steps in
  the [README](https://github.com/Harusame64/pictkura#readme) are needed again.
- Your library, settings, favourites and picks are kept.

## Known gaps

- **Neither build is signed.** Windows Defender has flagged pictkura as a trojan before
  (0.2.6 and 0.2.7); both were corrected by Microsoft as false positives. 0.2.8 was checked
  on a Windows machine, with these exact files, before it was published. If a warning
  appears anyway, see the [install page](https://harusame64.github.io/pictkura/en/install.html).
- **The installer, the MSI and the portable ZIP now contain the same `pictkura.exe`, byte
  for byte.** Before, the three copies differed by three bytes, so a correction for one did
  not reach the others.
- **One import case is not caught:** if a later import brings a *different* photo with the
  same name, size and timestamp as one already imported, it is treated as already imported
  and not copied.
- Still true from 0.2.7:
  - Video thumbnails depend on what the operating system can open, and always use the first
    frame.
  - No Linux build.
  - `.m2ts` and `.avi` appear in the grid but do not play inside the app.
  - Search results cannot be re-sorted (newest capture date first).
  - No UI to rebuild the search index.
  - Imports cannot be cancelled once started.
  - A RAW that declares no size anywhere shows no size.

  The full list is in the README.

# 日本語

pictkura 0.2.8 では、失敗が目に見えるようになり、取り込みで写真が落ちる不具合を直し、窓が
画面に収まるようになりました。

## 新しくなったところ

### 取り込み

- **別のフォルダにある同じ名前の写真は、両方とも取り込まれます。** 例:
  `DCIM/100MSDCF/DSC00001.ARW` と `DCIM/101MSDCF/DSC00001.ARW`。大文字と小文字だけが違う
  名前も同じです。
  - これまで: 1枚しかコピーされず、両方とも成功と報告されていました。
- **取り込みの画面の「?」の印**は、カードに同じ名前が2つ以上あり、ライブラリにある写真が
  この1枚かどうかがまだ分からない、という意味です。
  - その行は選んだままになります。
  - 取り込むときに中身を確かめます。すでにある写真は、2枚目を作りません。

### 失敗したとき

- **失敗は `pictkura.log` に記録されます。**

  | | |
  |---|---|
  | 場所（Windows） | `%APPDATA%\dev.harusame.pictkura\pictkura.log` |
  | 場所（macOS） | `~/Library/Application Support/dev.harusame.pictkura/pictkura.log` |
  | 開き方 | 設定 →「このアプリについて」→**「ログを開く」** |
  | 作られるとき | 失敗したときだけ。ファイルが無ければ、失敗は起きていません |
  | 送信 | しません。この機械の中だけに残ります |
  | 言語 | 常に英語。そのまま issue に貼れます |

- **失敗の知らせは、ツールバーのすぐ下に出ます。** 設定や取り込みの画面よりも手前です。
  クリックすると消えます。8秒たっても消えます。
- **失敗の文言は、アプリの言語で出ます。** Windows や macOS 自身が返す部分は、OS の言語の
  ままです。
- **ファイルについての失敗は、そのファイルの名前も出ます。**
- **失敗しても何も出なかった操作12か所で、知らせが出るようになりました。**

### 設定

- **`Ctrl`+`,`（Mac では `⌘`+`,`）で設定が開きます。** 一覧からも、写真を開いた画面からも
  使えます。
- **Mac では、メニューバーの pictkura → 設定…** からも開けます。

### Windows の自動再生

- **新しく入れた場合、pictkura は自動再生の候補に入りません。** 入れるには:
  設定 →**「USBやSDカードを挿したとき」**→**「「pictkura で写真を取り込む」を候補に出す」**
  をオンにします。
- **更新の場合は何も変わりません。** 自動再生の候補も設定も、そのまま残ります。

### 窓

- **窓は、開いた画面に収まる大きさで開きます。** はみ出すときだけ位置を動かします。
  - これまで: 1366×768 の画面や表示の拡大 150% では、窓が画面より大きく開き、下の端に
    手が届かないことがありました。
- **窓の最小の大きさは 960×520 です。** それより小さい画面では、画面に合わせて下がります。

### キー操作

- **`Esc` は、いちばん手前のものを閉じます。** 取り込みの画面・右クリックのメニュー・設定が
  対象で、奥で写真を開いていても同じです。
  - これまで: 奥の写真の画面が先に閉じることがありました。✕ の印があると、「ごみ箱へ
    移しますか」の確認が見えない場所に出ることもありました。
- **写真の画面をしばらく触らずにいたあとでも、1回目の `Esc` が効きます。**
  - これまで: 最初のキー入力が消え、`Esc` を2回押す必要がありました。
- **`Ctrl`+`F`（`⌘`+`F`）では★は付きません。** `F` だけなら、これまでどおり付きます。

## 0.2.7 からの更新

- **Windows**: 新しいインストーラを、そのまま上書きで実行します。
- **macOS**: ZIP を展開し、置いてある `pictkura.app` を新しいものに置き換えます。
  [README](https://github.com/Harusame64/pictkura/blob/main/README.ja.md) の Gatekeeper の
  手順が、もう一度必要です。
- ライブラリ・設定・お気に入り・選別の印は、そのまま残ります。

## まだ出来ないこと

- **どちらの配布物も署名していません。** Windows Defender はこれまでに pictkura を
  トロイの木馬として検出したことがあります（0.2.6 と 0.2.7）。どちらも Microsoft が
  誤検出として判定を修正しました。0.2.8 は、公開する前に、配るファイルそのものを Windows の
  実機に入れて確かめています。それでも警告が出た場合は
  [導入のページ](https://harusame64.github.io/pictkura/ja/install.html) を見てください。
- **インストーラ・MSI・ZIP の中の `pictkura.exe` は、1バイトも違わない同じファイルに
  なりました。** これまでは3つが3バイトずつ違い、1つの判定が修正されてもほかの2つには
  届きませんでした。
- **取り込みで見分けられない場合が1つあります:** 一度取り込んだあと、後の取り込みで
  名前・大きさ・日時がすべて同じ**別の**写真が来ると、取り込み済みと見なしてコピーしません。
- 0.2.7 から変わらないもの:
  - 動画のサムネイルは OS が開ける形式の範囲で、常に先頭のコマを使います。
  - Linux 版はありません。
  - `.m2ts` と `.avi` は一覧に出ますが、アプリ内では再生できません。
  - 検索結果は並び替えられません（撮影日の新しい順で固定）。
  - 検索索引を作り直す画面はありません。
  - 取り込みは、始めたら中断できません。
  - どこにも寸法を申告していない RAW は、寸法が空のままです。

  全部は README にまとめてあります。
