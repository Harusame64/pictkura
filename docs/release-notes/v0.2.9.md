pictkura 0.2.9 stacks RAW+JPEG pairs and bursts into one tile, adds slide and fade in full
screen, and keeps working when a USB drive or SD card comes and goes.

## What's new

### The grid

- **A RAW and a JPEG of the same shot are one tile.** Same folder, same name, same capture
  second (for example `IMG_0001.CR3` and `IMG_0001.JPG`). The tile shows the JPEG (or the HEIF, if
  that is the other file) with a `RAW+JPEG` badge in the corner (on narrow tiles, a mark of two overlapping squares).
  - In the grid, ★, ⚑, delete and selection apply to both files.
  - To see them separately: Settings → **Photo grid**.
- **A burst is one tile.** Shots from the same camera, each within 1 second of the one before,
  show as one tile with a `▤ Burst 12` badge.
  - The gap can be 0.5, 1 or 2 seconds (Settings → **Photo grid**), or bursts can be turned off.
  - Only cameras that record the capture time to a fraction of a second are stacked.
  - The cover is a shot marked ⚑, or else the first shot.
- **Scrolling fast no longer flashes rows of gray squares.** Thumbnails fade in over a quieter
  square as they arrive.

### Full screen

- **A RAW+JPEG pair shows the JPEG by default** (with a HEIF partner, the HEIF). Switch to RAW only, or to both (RAW, then
  JPEG), under Settings → **When you view a photo full screen**, or with the **RAW / JPEG**
  buttons in full screen.
  - With one side shown, ★, ⚑, ✕ and delete apply to both files of the pair.
- **Stepping to the next photo can slide or fade.** Settings → **When you view a photo full
  screen** → **When stepping to the next photo**: None, Slide (the default) or Fade.
  - The slideshow has its own choice, **Slideshow transition** (Fade by default).
  - Pressing a key or clicking while a photo is still moving finishes the move first, so
    ★, ⚑, ✕ and delete always apply to the photo you see.
  - Holding a key down does not animate. If your system is set to reduce motion, nothing moves.
- **Each slideshow photo stays for 3 seconds once it is fully shown.**
  - Before: the 3 seconds could keep restarting while thumbnails were being made, and the
    slideshow did not move on.

### When a file or folder is not there

- **A photo whose original is missing or cannot be opened says so.** The full-screen view shows
  why (missing, cannot be opened, not downloaded yet, cannot be displayed) and where pictkura
  looked.
- **A library folder that cannot be found is named in a notice,** with a button to remove it
  from the library. The files are not touched.
- **pictkura asks before you add a library folder, or choose an import destination, inside a
  temporary folder**, and keeps warning while one is in use. Temporary folders can be emptied
  by Windows or by cleanup tools.

### USB drives and SD cards (Windows)

- **"Safely Remove Hardware" works while pictkura is open.** pictkura lets go of a USB drive or
  SD card that holds a library folder when Windows asks to remove it.
  - Before: the removal was refused as long as pictkura was open.
- **Plugging it back in re-reads its library folders.** Photos added to it while it was away
  show up.
- **Unplugging it keeps its photos in the library**, ★ and ⚑ included, until it comes back.
- **Photos added to a FAT32 or exFAT card or drive are found at the next start.** Windows does
  not update folder times on those drives, so pictkura now walks them in full at every start.

### Smaller things

- **"Reading camera info… 0%" no longer stays on screen** after the pass has finished, and no
  longer appears at every start for photos that are only in the cloud.
- **The HEIC notice no longer says the HEVC extension is missing** when the real cause is a
  library folder that cannot be found.
- **Notices at the bottom of the window stack instead of covering each other.**
- **Confirmation dialogs name the action** (**Move to trash**, **Remove**) instead of **OK**.
  On macOS, `Esc` cancels them in any interface language.
- **Moving photos to a folder says "moved"**, not "exported".
- **The camera list on the left stays up to date** after thumbnails are made, after photos are
  removed, and after a file changes.
- **The Settings gear is a sharper icon.**

## Downloads

| You want | File |
|---|---|
| Windows 10/11, the usual case | `pictkura_0.2.9_x64-setup.exe` — no administrator rights |
| Windows, machine-wide install (for administrators) | `pictkura_0.2.9_x64_ja-JP.msi` / `_en-US.msi` |
| Windows, no installer | `pictkura_0.2.9_x64-portable.zip` |
| macOS 11+ (Apple Silicon) | `pictkura_0.2.9_arm64.zip` |

Neither build is code-signed, so Windows shows SmartScreen and macOS shows Gatekeeper on
first launch. The [README](https://github.com/Harusame64/pictkura#readme) walks through
both, including the extra steps macOS 15 needs.

## Upgrading from 0.2.8

- **Windows**: run the new installer over the old one.
- **macOS**: unzip the new `pictkura.app` and replace the old one. The Gatekeeper steps in
  the [README](https://github.com/Harusame64/pictkura#readme) are needed again.
- Your library, settings, favourites and picks are kept.
- **On the first start, pictkura reads the capture time of your existing photos again** to find
  bursts (all but RAW and TIFF files). This runs quietly in the background. Photos only in the
  cloud are skipped.

## Known gaps

- **Neither build is signed.** Windows Defender has flagged pictkura as a trojan before
  (0.2.6 and 0.2.7); both were corrected by Microsoft as false positives. 0.2.9 was checked
  on a Windows machine, with these exact files, before it was published. If a warning
  appears anyway, see the [install page](https://harusame64.github.io/pictkura/en/install.html).
- **Bursts shot in RAW only before 0.2.9 do not stack.** The capture time is read again only
  for JPEG, HEIC and similar images, not for RAW or TIFF, because those files are heavy.
  Bursts shot as RAW+JPEG stack through the JPEGs.
- **A USB drive or SD card (FAT32 or exFAT) in the library makes every start walk all
  folders**, not only the changed ones.
- Still true from 0.2.8:
  - If a later import brings a *different* photo with the same name, size and timestamp as one
    already imported, it is treated as already imported and not copied.
  - Video thumbnails depend on what the operating system can open, and always use the first
    frame.
  - No Linux build.
  - `.m2ts` and `.avi` appear in the grid but do not play inside the app.
  - Search results cannot be re-sorted (newest capture date first).
  - No UI to rebuild the search index.
  - Imports cannot be cancelled once started.

  The full list is in the README.

# 日本語

pictkura 0.2.9 では、RAW+JPEG の組と連写を一覧で1枚に重ね、大きく見る画面にスライドと
フェードを足し、USB メモリや SD カードの抜き差しに付いていけるようになりました。

## 新しくなったところ

### 一覧

- **同じ1枚の RAW と JPEG は、1つのタイルになります。** 同じフォルダ・同じ名前・撮影日時が
  同じ秒のものです（例: `IMG_0001.CR3` と `IMG_0001.JPG`）。タイルは JPEG（相手が HEIF なら
  HEIF）を見せ、右下に `RAW+JPEG` の印が付きます（細いタイルでは、四角が2枚重なった記号）。
  - 一覧での★・⚑・削除・選択は、2つのファイルの両方に効きます。
  - 分けて見たいときは: 設定 →**「一覧」**。
- **連写は1つのタイルになります。** 同じカメラで、前のコマとの間が1秒以内のものが、
  `▤ 連写 12` の印の付いた1枚にまとまります。
  - 間隔は 0.5秒・1秒・2秒から選べます（設定 →**「一覧」**）。連写をまとめないこともできます。
  - まとめるのは、撮影時刻を秒より細かく記録するカメラの写真だけです。
  - 表紙は ⚑ を付けたコマ、無ければ撮り始めのコマです。
- **勢いよくスクロールしても、灰色の四角が並んで見えなくなりました。** 届いたサムネイルから、
  控えめな色の四角の上に浮かびます。

### 写真を大きく見る画面

- **RAW+JPEG の組は、既定では JPEG を見せます**（相手が HEIF なら HEIF）。 RAW だけ、または両方（RAW → JPEG の順）に
  切り替えられます。設定 →**「写真を大きく見るとき」**か、大きく見る画面の **RAW / JPEG** の
  ボタンで切り替えます。
  - 片方だけを見せているときは、★・⚑・✕・削除が組の両方に効きます。
- **次の写真へ送るときに、スライドかフェードで動くようになりました。** 設定 →
  **「写真を大きく見るとき」**→**「次の写真へ送るときの動き」**で、なし・スライド（既定）・
  フェードから選べます。
  - スライドショーは**「スライドショーの切り替え」**で別に選べます（既定はフェード）。
  - 動いている最中にキーを押したりクリックしたりすると、先に動きを終わらせます。★・⚑・✕・
    削除は、いつも見えている写真に効きます。
  - キーを押しっぱなしにして送るときは動きません。OS の設定でアニメーションを減らしている
    ときも動きません。
- **スライドショーは、写真がすっかり出てから3秒見せます。**
  - これまで: サムネイルを作っている間は3秒が数え直しになり続け、次へ進まないことが
    ありました。

### ファイルやフォルダが見つからないとき

- **原本が無い・開けない写真は、そう言います。** 大きく見る画面に、理由（無い・開けない・
  まだダウンロードされていない・表示できない）と、探した場所が出ます。
- **見つからないライブラリのフォルダは、知らせで名前を出します。** ライブラリから外す
  ボタンも付きます。ファイルには触りません。
- **一時フォルダの中をライブラリに足すとき、取り込み先に選ぶときは、先に確かめます。**
  使っている間も知らせ続けます。一時フォルダは、Windows や掃除のツールに空にされることが
  あるためです。

### USB メモリと SD カード（Windows）

- **pictkura を開いたままでも「ハードウェアの安全な取り外し」ができます。** ライブラリの
  フォルダがある USB メモリや SD カードを、Windows が取り外そうとしたときに手放します。
  - これまで: pictkura が開いている間は、取り外しが断られていました。
- **挿し直すと、そのライブラリのフォルダを読み直します。** 外している間に足した写真も出ます。
- **抜いても、その写真はライブラリに残ります。** ★ と ⚑ も、挿し直すまでそのままです。
- **FAT32・exFAT のカードやドライブに足した写真は、次に起動したときに見つかります。**
  Windows はこれらのドライブでフォルダの時刻を動かさないので、起動のたびに全部たどるように
  しました。

### 細かいところ

- **「カメラ情報を読み取り中… 0%」が、終わったあとも出たままになることはなくなりました。**
  クラウドにしか無い写真のために、起動のたびに出ることもなくなりました。
- **HEIC の知らせが、「HEVC の拡張機能が無い」と言わなくなりました**——本当の理由が
  「ライブラリのフォルダが見つからない」だったときに、そう出ていました。
- **窓の下に出る知らせは、重ならずに積み重なります。**
- **確認の画面のボタンは、何をするかを名乗ります**（**ゴミ箱へ移動**・**外す**）。**OK** では
  ありません。macOS では、どの表示言語でも `Esc` で取り消せます。
- **フォルダへ移したときの知らせは「移動」と言います。**「書き出し」ではありません。
- **左の「カメラとメディア」の一覧が、遅れずに付いてきます。** サムネイルができたとき、写真を
  外したとき、ファイルが変わったときです。
- **設定の歯車を、くっきりした形にしました。**

## 0.2.8 からの更新

- **Windows**: 新しいインストーラを、そのまま上書きで実行します。
- **macOS**: ZIP を展開し、置いてある `pictkura.app` を新しいものに置き換えます。
  [README](https://github.com/Harusame64/pictkura/blob/main/README.ja.md) の Gatekeeper の
  手順が、もう一度要ります。
- ライブラリ・設定・お気に入り・選んだ写真は、そのまま残ります。
- **最初の起動で、今ある写真の撮影時刻を読み直します**（連写を見つけるため。RAW と TIFF は
  除きます）。裏で静かに進みます。クラウドにしか無い写真は飛ばします。

## まだできないこと

- **どちらも署名していません。** Windows Defender は以前、pictkura をトロイの木馬と判定した
  ことがあります（0.2.6 と 0.2.7）。どちらも Microsoft が誤検知として取り下げました。
  0.2.9 は、公開する前に、この配布物そのものを Windows の機械で確かめています。それでも警告が
  出たときは、[インストールのページ](https://harusame64.github.io/pictkura/ja/install.html)を
  見てください。
- **0.2.9 より前に RAW だけで撮った連写は、重なりません。** 撮影時刻を読み直すのは JPEG・HEIC
  などの画像だけで、RAW と TIFF は読み直しません（ファイルが重いため）。RAW+JPEG で撮った
  連写は、JPEG の側で重なります。
- **ライブラリに USB メモリや SD カード（FAT32・exFAT）があると、起動のたびにすべての
  フォルダを確かめます。** 変わったところだけ、にはなりません。
- 0.2.8 から変わらないもの:
  - あとの取り込みで、取り込み済みの写真と名前・大きさ・日時が同じ*別の*写真が来ると、
    取り込み済みとみなしてコピーしません。
  - 動画のサムネイルは OS が開けるものに限り、いつも最初のコマです。
  - Linux 版はありません。
  - `.m2ts` と `.avi` は一覧には出ますが、アプリの中では再生できません。
  - 検索結果は並べ替えられません（撮影日の新しい順）。
  - 検索の索引を作り直す画面はありません。
  - 取り込みは、始めたら取り消せません。

  すべては README に書いてあります。
