pictkura 0.2.2 is a small release about RAW files: Canon's HDR PQ shots get a thumbnail at
last, and every RAW now records the sensor's own size alongside the preview's.

## What's new

**Thumbnails for Canon's HDR PQ RAW files.** A CR3 shot in HDR PQ carries its preview as
HEVC rather than JPEG — 10-bit PQ will not fit in a JPEG — and there is no usable JPEG
anywhere else in the file. Those files used to sit in the grid as an empty frame. pictkura
now lifts the HEVC preview out of the file, wraps it as a minimal HEIF, and hands it to the
same decoder it already uses for HEIC, so the picture appears.

Decoding one of these costs about a quarter to four tenths of a second, where reading a JPEG
preview takes a few milliseconds, so it only happens when the file holds no usable JPEG at
all. Ordinary CR3 files are untouched and just as fast as before.

This one is Windows only for now, and it leans on the same two components as HEIC: the free
HEIF Image Extensions for the container, and the HEVC Video Extensions for the pixels (many
Windows 11 machines already have it). Without them the file keeps its empty frame, and
nothing will prompt you — the notice inside the app that offers to install them counts
HEIC photos, not RAW. On macOS these files still show an empty frame too, because the HEIF
decoder there is not wired up yet.

**RAW files record the sensor's size, not the preview's.** `width`/`height` for a RAW used to
hold the size of the embedded preview — 1620x1080 for an HDR PQ CR3 — while the sensor's own
6000x4000 went unrecorded. Both are kept now, read from what the file declares (the `CMT1`
box in a CR3, the Exif IFD in a CR2 or an ARW, and so on). The grid draws RAW tiles at the
sensor's aspect ratio, which is close to the preview's but not always equal.

Existing libraries correct themselves once, quietly in the background, on the first launch
after the update. Nothing needs to be rescanned and no thumbnail is rebuilt: this pass reads
the size that the file declares and never decodes a picture. Files on a drive that is not
connected, or that live only in the cloud, are left alone until the day they can be read.

## Downloads

| You want | File |
|---|---|
| Windows 10/11, the usual case | `pictkura_0.2.2_x64-setup.exe` — no administrator rights |
| Windows, machine-wide install (for administrators) | `pictkura_0.2.2_x64_ja-JP.msi` / `_en-US.msi` |
| Windows, no installer | `pictkura_0.2.2_x64-portable.zip` |
| macOS 11+ (Apple Silicon) | `pictkura_0.2.2_arm64.zip` |

Neither build is code-signed, so Windows shows SmartScreen and macOS shows Gatekeeper on
first launch. The [README](https://github.com/Harusame64/pictkura#readme) walks through
both, including the extra steps macOS 15 needs.

## Upgrading from 0.2.1

On Windows, run the installer over the top of the old one. On macOS, unzip the new
`pictkura.app` and replace the old one where you keep it — the Gatekeeper steps in the
[README](https://github.com/Harusame64/pictkura#readme) apply again, because the app you
just downloaded is a new file as far as macOS is concerned.

Either way, your library, settings, favourites and picks stay where they are.

## Known gaps

The HDR PQ preview above is decoded by the operating system, so it needs Windows and the
two extensions named above. Video thumbnails are Windows-only for the same reason. `.m2ts` and `.avi` appear in the grid
but do not play in the app. There is no sort order for search results (newest capture date
first), no UI to rebuild the search index, and imports cannot be cancelled once started. The
full list is in the README.

# 日本語

pictkura 0.2.2 は小さな更新で、中身はRAWの話が2つです。Canon の HDR PQ で撮った RAW に
サムネイルが出るようになり、RAW は原本（センサー）の寸法も控えるようになりました。

## 新しくなったところ

**Canon の HDR PQ で撮った RAW にサムネイルが出ます。** HDR PQ で撮った CR3 は、
プレビューを JPEG ではなく **HEVC** で書きます——10ビットの PQ は JPEG では表せません——
そして、そのファイルには使える JPEG が1枚も入っていません。これまでは一覧に枠だけが
並んでいました。pictkura はこの HEVC のプレビューをファイルから取り出し、最小の HEIF に
包み直して、HEIC で既に使っているデコーダに渡すようにしました。絵が出ます。

1枚あたり0.25〜0.4秒ほどかかります（JPEG のプレビューを読むのは数ミリ秒です）。
そのため、**使える JPEG が1枚も無かったときだけ**この道を通ります。ふつうの CR3 は
これまでどおりの速さです。

いまのところ Windows のみで、HEIC と同じ2つの部品に頼ります——コンテナのための
**HEIF Image Extensions**（無料）と、画素のための **HEVC Video Extensions**（多くの
Windows 11 には既に入っています）。入っていなければ枠だけのままで、しかも案内は
出ません——アプリの中で導入を勧める帯が数えているのは HEIC の写真で、RAW は数に
入らないからです。macOS でも枠だけになります。HEIF のデコーダをまだ繋いでいません。

**RAW は原本の寸法を控えます（プレビューの寸法ではなく）。** これまで RAW の
`width`/`height` に入っていたのは**埋め込みプレビューの寸法**で（HDR PQ の CR3 なら
1620x1080）、センサーの 6000x4000 はどこにも残っていませんでした。いまは両方を持ちます。
値はファイルの申告から読みます（CR3 なら `CMT1` の箱、CR2 や ARW なら Exif IFD、など）。
一覧の枠は原本の縦横比で描かれます——プレビューとほぼ同じですが、常に同じとは限りません。

すでにあるライブラリは、更新後の初回起動で一度だけ、背景で静かに直ります。取り込み直しは
要りませんし、サムネイルも作り直しません（この掃き寄せは申告を読むだけで、絵は1枚も
起こしません）。繋いでいないドライブの中や、クラウドにしか実体が無いファイルは、
読める日が来るまで触りません。
