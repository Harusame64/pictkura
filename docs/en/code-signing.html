Signing, and how to verify a download

Whether the file you downloaded is the file that was published here. The pictkura downloads are not code signed. So instead: who builds them and from what, and how to check a file yourself.

Published  2026-09-01 Last revised  2026-09-01

1Current signing status

The Windows downloads (.exe, .msi, portable) are not code signed. SmartScreen will therefore show "Windows protected your PC" the first time you run one. The macOS .app carries an ad-hoc signature only and is not notarized by Apple, so Gatekeeper will stop it.

The installation guide walks through both, screen by screen. The warning is the expected consequence of shipping unsigned software, not a fault. But "the warning is normal" is a bad habit to teach, so the next section gives you something to check instead.

2Who builds them, and from what

Releases are not uploaded from a personal machine. A tag on the public GitHub repository triggers a GitHub Actions workflow (release.yml) that builds the artifacts and attaches them to the release.

So the source and the build definition are both public, and every run is listed on GitHub (the logs themselves expire after 90 days by default, so for older versions only the listing remains).

3Checking the file you have

The check is to ask GitHub for a number GitHub computed. Every release asset carries a SHA-256 that GitHub calculates from the bytes it stores. It is not a number we typed in.

What it catches is a copy handed out by some other site, or a file altered on its way to you. pictkura is listed on download portals as well, so this matters most when checking something you did not get from GitHub itself.

Ask GitHub — macOS (v0.2.6 is an example — use the tag of the version you have; it is in the filename)

curl -s https://api.github.com/repos/Harusame64/pictkura/releases/tags/v0.2.6 | grep -E '"name"|"digest"'

Windows (PowerShell)

(Invoke-RestMethod https://api.github.com/repos/Harusame64/pictkura/releases/tags/v0.2.6).assets | Select-Object name, digest

Hash what you downloaded and compare

Get-FileHash .\pictkura_*_x64-setup.exe -Algorithm SHA256  (on macOS, shasum -a 256 pictkura_*_arm64.zip)

When comparing  GitHub's value carries a sha256: prefix and Get-FileHash prints upper case. Drop the prefix and compare ignoring case. If nothing at all is printed on Windows, the file is not in that folder — Get-FileHash exits silently, without an error, when the pattern matches nothing. The wildcards above are written for -setup.exe and arm64.zip; substitute the filename to check an MSI or the portable zip.

The download page walks through the steps. All this check tells you is that the file you hold is byte for byte the asset GitHub is serving right now. It is not evidence that the contents are safe, and it would not reveal a compromise of the GitHub account itself — GitHub recomputes the digest for whatever asset is put there.

Releases also carry a SHA256SUMS.txt (from v0.2.5 onward; earlier ones do not). It is convenient, but it is a list we wrote, sitting in the same place as the files it vouches for. Where the whole distribution path could be replaced, asking GitHub is the stronger of the two.

4What the app sends

Separately from signing, what the app transmits is meant to be checkable too. Its only outbound connection is the update check, and all it sends is "this version of pictkura is asking". No photos, no file names, no folder paths. The check is on by default and can be switched off in the settings.

The details are in the privacy policy and in the manual, under "Update notices".
