署名と、配布物の確かめ方

ダウンロードしたファイルが、ここで公開したものと同じかどうか。いま pictkura の配布物には署名がありません。そのぶん、誰がどこから作っているかと、手元のファイルを自分で確かめる手順を書いておきます。

制定  2026-09-01 最終改定  2026-09-01

1いまの署名の状態

Windows 向けの配布物（.exe / .msi / portable）はコード署名していません。そのため初回の実行で SmartScreen の「WindowsによってPCが保護されました」が出ます。macOS 向けの .app は ad-hoc 署名のみで、Apple の公証を受けていません。そのため Gatekeeper に止められます。

どちらも、画面の進み方はインストールの案内に画面ごとに書いてあります。警告が出ること自体は、このアプリが未署名であることの当然の結果で、異常ではありません。ただし「警告が出るのが普通」で片づけるのは危ないので、代わりに確かめる手段を次に置きます。

2誰が、どこから作っているか

配布物は手元の PC からは上げていません。GitHub の公開リポジトリに付けたタグから、GitHub Actions のワークフロー（release.yml）が組み立て、そのまま Releases へ載せています。

つまり、公開されているソースと、公開されているワークフローの定義から、何がどう作られたかを誰でも読めます。どの実行があったかも GitHub に残ります（ログの本文は既定で90日で消えますので、古い版のぶんは一覧だけになります）。

3手元のファイルを確かめる

確かめ方は、GitHub が自分で計算した値を GitHub に訊くことです。各リリースの資産には、GitHub が保管しているバイト列から算出した SHA-256 が付いています。こちらが打ち込んだ数字ではありません。

これで見分けられるのは、他所のサイトで配られているコピーや、通信の途中で差し替えられたファイルです。pictkura は掲載サイト経由でも配られているので、GitHub 以外から手に入れたものを確かめるときに、いちばん効きます。

GitHub に訊く — macOS（v0.2.6 は例です。手元のファイル名にある版に置き換えてください）

curl -s https://api.github.com/repos/Harusame64/pictkura/releases/tags/v0.2.6 | grep -E '"name"|"digest"'

Windows（PowerShell）

(Invoke-RestMethod https://api.github.com/repos/Harusame64/pictkura/releases/tags/v0.2.6).assets | Select-Object name, digest

手元のファイルを計算して見比べる

Get-FileHash .\pictkura_*_x64-setup.exe -Algorithm SHA256　（macOS は shasum -a 256 pictkura_*_arm64.zip）

見比べるときの注意　GitHub の値には sha256: が付き、Get-FileHash は大文字で出します。前置きを外し、大小を無視して比べてください。Windows で何も表示されないときは、そのフォルダにファイルが無いときです——パターンが当たらないと Get-FileHash はエラーも出さずに終わります。上のワイルドカードは -setup.exe と arm64.zip に合わせてあるので、MSI や portable を確かめるときはファイル名を置き換えてください。

手順の詳しい説明はダウンロードのページにあります。この確認で言えるのは「手元のファイルが、いま GitHub にある資産と1バイトも違わない」ことだけです。中身が安全であることの証明ではありませんし、GitHub のアカウントごと乗っ取られた場合は、これでは分かりません——差し替えられた資産の digest は、GitHub が計算し直すからです。

各リリースには SHA256SUMS.txt も添えています（v0.2.5 以降。それより前には付いていません）。手軽ですが、これは配布物と同じ場所に置いた、こちらが作った一覧です。配布経路ごと差し替えられる状況では、上の GitHub に訊く方法のほうが強いことは知っておいてください。

4アプリが外へ出す通信

署名の有無とは別に、アプリが何を送るかも確かめられる形にしてあります。外向きの通信は新しいバージョンの確認だけで、送るのは「pictkura のこのバージョンが確認しています」という名乗りのみ。写真もファイル名もフォルダの場所も送りません。この確認は既定で有効ですが、設定で切れます。

詳しくはプライバシーポリシーと、取扱説明書の「新しいバージョンのお知らせ」に書いてあります。
